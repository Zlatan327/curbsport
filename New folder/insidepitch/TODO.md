# Delivery outcomes

- [x] **Auth (Login/Register):** High-impact typography, dark mode background, neon green primary action button. Login and register call the existing auth endpoints, store the returned JWT in localStorage, attach it as a Bearer header, restore the local session, and show loading/error states.
- [x] **Mobile application shell and navigation:** Constrain the app to a mobile-width container (`max-w-md mx-auto`) even on desktop, with a fixed Bottom Navigation bar (Feed, Map, Add, Profile), clear active state and space for device safe areas.
- [x] **Feed and pitch cards:** Render a list of reusable `PitchCard` components loaded with SWR from `GET /api/pitches?cityId=X`; display DRY, BUILDING and LIVE status treatments, a prominent LIVE indicator, and a gritty warning for GHOST pitches using the copy “👻 Unverified - Does ball fly here?”. Show useful loading, empty, error, and retry states.
- [x] **Pitch detail, voting, sets, and banter:** Implement `/pitches/:id` with a large map placeholder, pitch stats, verification state, community up/down voting through `POST /api/pitches/:id/vote` with `{ isUp: boolean }`, and INFO, SETS (Lobbies), BANTER (Chat) tabs. The Sets tab shows who is playing and tactile join controls; lobby creation and joining use `GET` and `POST /api/lobbies`. Banter uses `GET` and `POST /api/banter?pitchId=X`, displays message history, a composer, loading/error/pending feedback, and quick-tap chips “We dey ground!” and “Any keeper dey?”.
- [x] **Add Pitch, Map, and Profile:** Build a heavily stylized Add Pitch drop-a-pin form with validation and honest treatment of missing backend capabilities; deliver the Map and Profile destinations required by bottom navigation, reusing available pitch/auth data and showing accurate empty or placeholder states where the API has no dedicated endpoint.
- [x] **API integration and export:** Keep the work frontend-only; all API calls target `http://localhost:4000/api` by default, attach a localStorage JWT as a `Bearer` header, and use a shared typed API/SWR layer with normalized errors. Keep the source runnable and export-ready in the `client/` folder, with setup instructions and backend assumptions documented.
